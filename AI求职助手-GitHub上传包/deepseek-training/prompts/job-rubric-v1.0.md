# 岗位评分表 v1.0

> 运行时提示词以 `scoring-core.js` 中的 `JOB_RUBRIC_SYSTEM_PROMPT` 为准。本文件用于评审字段和规则。

## 目标

只从岗位招聘信息中提取固定评分条款。此阶段不读取简历、不输出分数、不评价候选人。

岗位评分表生成后，同一岗位后续只更新证据矩阵，不再由模型重新拆分要求。

## 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 系统按顺序生成 `R01`、`R02` 等固定编号 |
| `category` | 枚举 | `hard`、`core`、`bonus` |
| `dimension` | 枚举 | 七个固定评分维度之一 |
| `source_section` | 枚举 | `responsibilities`、`qualification`、`other` |
| `requirement` | 字符串 | 可独立判断的要求摘要 |
| `jd_quote` | 字符串 | 支撑该要求的岗位原文 |
| `evidence_rule` | 字符串 | 简历中出现哪些事实才算可判断证据 |

## 类别

- `hard`：学历、专业、毕业年份、证书、地点、到岗时间、实习周期等门槛，不进入匹配分。
- `core`：岗位必须掌握或承担的能力、知识、经历和行为，权重 `1.0`。
- `bonus`：岗位明确写为“优先、加分、有则更好”的要求，权重 `0.5`。

## 七个评分维度

| 维度键 | 展示名称 | 综合权重 |
| --- | --- | ---: |
| `core_skills` | 核心专业技能 | 25% |
| `domain_knowledge` | 行业与岗位知识 | 10% |
| `experience` | 项目与实习证据 | 20% |
| `complexity` | 任务复杂度与独立程度 | 10% |
| `education` | 教育、专业与证书 | 10% |
| `behavior` | 沟通与协作行为 | 10% |
| `conditions` | 到岗、语言与其他条件 | 10% |

## 固定规则

1. 必须同时覆盖“岗位职责”和“任职要求”，不能只提取后者。
2. 岗位职责中的主要任务默认归为 `core`。
3. 一个可独立判断的条件只保留一行，并合并语义重复项。
4. 通常提取 8 至 15 行，最多 20 行。
5. “优先”内容只能标为 `bonus`。
6. 不把行业常识补写成岗位要求。
7. 岗位没有涉及的维度不进入综合分；同一条款一旦锁定，不得因为简历内容少而被删除。
