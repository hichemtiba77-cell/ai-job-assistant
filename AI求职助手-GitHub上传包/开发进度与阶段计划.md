## 二、当前技术结构

```text
浏览器（双击测试）
→ index.html 上传PDF并填写岗位
→ pdf-extractor.js 在浏览器内读取PDF文字
→ browser-api.js 测试直连 DeepSeek API
→ report.html 显示四个标签页、硬性门槛提示和评分明细

浏览器（正式本地服务）
→ privacy.html 阅读数据说明并勾选同意
→ index.html 上传PDF并填写岗位
→ pdf-extractor.js 在浏览器内读取PDF文字
→ 本地后台 /api/analyze（SSE实时推送分析阶段与用时）
→ 查询SQLite结果缓存（命中则直接返回并提示）
→ DeepSeek API（评分表阶段 + 证据阶段）
→ 程序按固定评分表计分，硬性条件不满足时封顶
→ report.html 显示四个标签页、硬性门槛提示和评分明细
→ POST /api/forget 按原文删除缓存和关联调用日志
```

- 缓存默认保留30天，`CACHE_TTL_DAYS`可调整；服务启动时清理过期记录
- 报告页“删除本次记录”同时清空`sessionStorage`中的输入和报告

- 本地缓存：`data/cache.db`（Node 24内置`node:sqlite`，WAL模式，已加入`.gitignore`）
- 双击模式仍为浏览器内存缓存；SQLite缓存只在本地服务模式下生效

- 模型API别名：`deepseek-flash`
- 服务模型：`DeepSeek-V4.1-Flash-1017`
- API地址：`https://api.deepseek.com`
- 正式模式密钥只保存在`.env.local`或被忽略的服务器环境变量中
- 当前`config.local.js`只保留空占位；填入密钥后才启用双击直连，留空自动使用模拟结果
- `config.local.js`不得随公开仓库、公开链接或公网部署发布
- 无密钥时自动使用本地模拟结果

## 四、当前阶段的工作

### 阶段4：提示词和评分效果验证

目标：确认同一份简历和岗位在不同测试案例中能够得到稳定、有证据、可解释的结果。

已完成（2026-11-07 自动评测）：

- 建立T01–T07七组虚构案例，覆盖完整简历、明显不匹配、无量化成果、到岗时间未知、大量无关信息、提示词注入，以及硬性专业条件冲突。
- 每组案例独立调用3次：总分极差0–12分（平均4分），T02/T07完全一致，T01/T05/T06极差≤3分；T03极差12分为当前最高，说明证据等级仍有提升空间。
- 证据核对表逐条给出简历原文和JD原文；未找到证据的条目保留在评分表中并计0分，不删除分母、不隐藏低分。
- 硬性条件与综合分分开判断：到岗时间未写时标记“待确认”，未自动判为不具备；明确不满足时综合分封顶44分，原始证据分仍保留。
- 收紧证据提示词：简历写出的学历、专业、证书、到岗时间与硬性条件冲突时，必须标记`unmet`，不能被同一行的部分相关证据带成`unknown`。T07（教育学本科应聘要求统计/数学/计算机专业的数据分析师）连续3次均触发封顶，分数为76→44、73→44、73→44。
- T06注入文字未改变模型角色、未泄露系统提示词、未产生满分。
- 接口失败时返回明确错误，不静默切换到模拟分数；界面显示失败阶段并可一键重试。
- 评测报告：直接打分基线`output/eval/baseline-2026-11-07T08-35-20.md`；语义近似改写`output/eval/consistency-2026-11-07T08-38-17.md`；旧版逐条一致性`output/eval/consistency-2026-11-07T06-42-57.md`。
- 评测结论：直接打分更稳定，但T06、T07显示它会忽略无关经历和硬性专业门槛；评分表流程并非在所有案例上都更稳定（T03极差12分），其价值主要在逐条证据、门槛约束和结果可复现，而不是单纯的低方差。
- 已确认报告页在真实浏览器中的展示：T07硬门槛横幅、原始分73与封顶44、3个已评估维度的权重/贡献、协议与提示词指纹、删除按钮和隐私链接均正常。
