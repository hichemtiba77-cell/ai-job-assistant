## 二、当前技术结构

```text
浏览器（双击测试）
→ index.html 上传PDF并填写岗位
→ pdf-extractor.js 在浏览器内读取PDF文字
→ browser-api.js 测试直连 DeepSeek API
→ report.html 显示四个标签页

浏览器（正式本地服务）
→ index.html 上传PDF并填写岗位
→ pdf-extractor.js 在浏览器内读取PDF文字
→ 本地后台 /api/analyze
→ DeepSeek API
→ report.html 显示四个标签页
```

- 模型API别名：`deepseek-flash`
- 服务模型：`DeepSeek-V4.1-Flash-1017`
- API地址：`https://api.deepseek.com`
- 正式模式密钥只保存在`.env.local`或被忽略的服务器环境变量中
- 当前队内测试直连密钥只保存在被Git忽略的`config.local.js`
- `config.local.js`不得随公开仓库、公开链接或公网部署发布
- 无密钥时自动使用本地模拟结果

## 四、当前阶段的工作

### 阶段4：提示词和评分效果验证

目标：确认同一份简历和岗位在不同测试案例中能够得到稳定、有证据、可解释的结果。

需要完成：

- 使用完整简历、短简历、明显不匹配岗位和信息不足材料进行测试。
- 检查每条结论是否引用简历原文。
- 检查材料不足时仍能给出低分，而不是隐藏分数。
- 检查硬性条件是否与综合分分开。
- 检查修改建议是否要求虚构经历。
- 检查同一组材料重复分析的分数波动。
- 根据结果调整岗位评分表和简历证据矩阵。

完成标准：

- 至少6组案例完成人工检查。
- 评分能由逐条证据解释。
- 不编造经历。
- 软硬件条件未知时明确标记，不自动判为不具备。
- DeepSeek失败时显示明确错误，不静默使用不同口径的模拟分数。

## 五、部署建议

现在仍不公开部署。队内测试使用私密压缩包和`config.local.js`，评分案例验证完成后，再部署仅项目组可访问的私密预览，确认：

- DeepSeek接口在部署环境中可用。
- 密钥没有进入公开浏览器文件。
- 手机和电脑均可完成输入与报告查看。
- 接口超时和额度不足时能回退。

公开测试部署放在账号、数据库和PDF导入完成之后。
