# AI 求职助手算法优化实施方案

日期 2026-11-09
当前版本 `scorecard-v1.3` · 拟议版本 `scorecard-v1.4`

## 1. 目标与范围

把诊断结果拆成三个可独立核查的判断：岗位要求是什么、简历能证明什么、程序如何根据证据计分。优先减少虚假证据得分、误判硬性条件和模型输出不完整造成的误导，再改善同一材料反复分析时的分数波动。同时尽量减少提交给模型和留在本机的个人信息。

改造范围包括评分核心、两阶段模型调用、输入脱敏、缓存删除和评测工具。报告只增加解释算法结果所需的字段。继续使用现有 Node 服务和浏览器共享的评分逻辑。

## 2. 现状与优先级

| 优先级 | 已确认的问题 | 本轮交付 |
| --- | --- | --- |
| P0 | 评测脚本用 `fresh` 跳过结果缓存，岗位评分表仍可复用，无法区分岗位提取和简历证据各自带来的波动。统计还会把 `null` 转成 0，并以展示编号 R01、R02 对齐不同运行的要求。 | 分开测全链路和固定评分表，按原文锚点对齐，单独统计无分、失败和缺项。 |
| P0 | 原文可定位只能证明一句话存在。模型可以引用真实但无关的简历内容，并给出过高等级或错误门槛判断。 | 引入可核查的证据编号，门槛只接受明确且可对照的候选人事实。 |
| P0 | 自动脱敏主要靠格式规则，自由文本仍可能有漏网信息。报告删除目前需要再次提交材料。 | 增加发送前预览和编辑，加入离线模式，提供不带原文的删除凭证。 |
| P1 | 岗位要求的切分、分类和证据等级仍依赖模型。同一句被切成不同粒度时，评分分母和权重会变。 | 由程序先划分候选条款，模型只返回条款编号和分类。统一证据等级判据。 |
| P1 | 当前“置信度”混合了材料完整度、证据覆盖与门槛未知比例，容易被理解成结果正确的概率。 | 分开报告材料覆盖、证据核验和门槛状态；硬门槛和匹配分分别展示。 |

历史记录中，旧提示词版本在 T01–T07 上每例运行 3 次，总分极差 0–12 分，T03 极差 12 分。该结果用于定位重点案例。正式对照需用同一模型与同一批用例重新运行 v1.3 和候选版。v1.3 当前已有 46 项自动化测试通过，真实模型的新版基线尚待采集。

## 3. 目标流程与模块修改

```text
简历 / 岗位文字
  → 本地规范化、脱敏、预览确认
  → 程序生成岗位条款编号和简历证据片段编号
  → 模型关联岗位条款与证据片段
  → 程序校验引用、比较硬性条件、计算匹配分
  → 报告展示匹配分、门槛状态、证据覆盖及待确认项
```

### 3.1 岗位评分表固定到原文条款

- 在 `scoring-core.js` 增加岗位条款解析。按职责、任职要求等标题、列表标记和句界切分，保留规范化文本的起止位置、段落和出现顺序。遇到“且”“或”、数值区间和“满足任一即可”时先保留完整表达，由结构校验决定能否拆分。
- 每条记录包含 `clauseId`、`start`、`end`、`quote`、`category`、`dimension` 和 `policyVersion`。程序生成 `clauseId`，报告可以另用 R01、R02 展示。模型仅在已给出的候选条款中标注核心项、加分项和门槛候选，并返回维度和分类理由。
- 对明确写有“优先”“加分”的子句优先识别为加分项。同一句同时包含必需条件和加分条件时分别处理。模型指向不存在的条款、输出冲突分类或整段漏判时记录原因。无法可靠切分时进入待确认，禁止模型用重新编写的条款替换岗位原文。
- 超长 JD 分批解析，合并时按原文位置去重。凡是因资源上限未分析的条款须计入报告状态。若关键条款未覆盖，暂停发布完整总分。首版用人工标注条款和保留集验证切分，观察职责漏检及加分项被误设为门槛的比例。

### 3.2 简历证据从自由文本改为引用编号

- 在共享核心里把脱敏后的简历切成教育、经历、技能等片段。一个证据片段保留项目或组织上下文、时间和相邻句，避免把前一个项目的团队指标归给后一个项目。模型提交 `clauseId`、`spanIds`、候选人动作、相关性理由和证据状态。报告引用由程序按片段位置回填。
- 按条款从简历检索候选片段，首版采用固定别名表和文本检索，同时保留必要上下文。对未找到候选片段的条款，若材料很短则在预算内扩大检索范围。检索为空只能说明系统未找到，不能推出候选人没有该能力。评测中同时量化候选检索召回率和最终证据关联准确率。
- 定义三个独立层级。相关度区分直接对应、部分对应和无关；证据强度区分笼统自述、具体动作、动作加可归属成果；主导度只有出现可归属的个人职责才允许进入较高等级。仅有关键词、团队成果或证据跨项目时降档。数字必须和证据中的动作同属一个片段或明确关联的相邻片段。
- 区分“已检查且未找到”“有证据但不足以判断”“模型未完成检查”“证据冲突”四种情况。部分批次缺失时只重试缺失批次；重试后仍不完整，输出可核查的已完成条目与未评估项。对引用真实但语义不相关的情况纳入人工复核，避免把位置校验当成语义校验。

### 3.3 门槛使用三值逻辑，匹配分保留可复算性

- 首批门槛只自动判断明示且能结构化对比的类型，如学历层次、毕业年份、每周到岗天数、实习周期。学历需区分在读和已取得。到岗天数、实习周期需要明确单位；月份和周数含混时待确认。专业范围、证书等条件仅在写法明确、对照范围已定义时判断，其余交给用户复核。
- 每个条件返回 `met`、`unmet` 或 `unknown`，附岗位条款和简历证据编号。AND 只要有明确不满足就为不满足，所有子项满足才为满足。OR 只要有一项满足就为满足，所有子项明确不满足才为不满足。缺证、上下文冲突、边界不清时保持待确认。
- 首轮保留 v1.3 的相关度、证据强度和主导度 **40∶35∶15**，维度权重也先冻结。使用全精度完成聚合后再对展示值取整。有效评分表中已检查且无证据的条目保留在分母，计 0；未评估的条目禁止填 0。当必评条目未处理时，整体匹配分为 `null`，只展示已核实条目。
- 新报告以“匹配分 + 硬性门槛状态”并列展示。保留旧版 `score` 封顶字段供旧报告和调用方读取，新字段 `matchScore` 表示未经门槛封顶的匹配分。`fitLevel` 的等级阈值首轮保持不变，报告在门槛未通过时明确标出理由，避免高分掩盖硬性条件冲突。
- 将启发式 `confidenceScore` 降为旧版兼容字段。新报告分别给出岗位条款已评估比例、核心条款已核验比例和门槛待确认数。覆盖比例的分母和分子可点开核查。没有人工校准集时，界面不把这些比例解释为正确概率。

### 3.4 隐私控制覆盖发送、缓存和删除

- `app.js` 和 `browser-api.js` 在发送前展示实际拟提交文本和被遮盖的字段，允许本地编辑。服务端继续独立脱敏，避免绕过网页入口。给脱敏规则加版本号，用合成姓名、电话、证件、地址、不同 OCR 空格和全角字符测试漏遮盖，同时验证不误伤技能、日期、到岗单位和项目指标。
- 新增本地离线模式。仅运行本地规则，提供材料完整度、明确条件和证据检查清单；不生成需要语义判断的匹配分。浏览器同意模型分析后，才可请求外部模型；连接失败时由用户决定是否继续离线检查。
- 保留现有 30 分钟内存默认值和磁盘显式开启策略。缓存键纳入评分策略、脱敏规则、模型及端点标识。给报告发独立的随机删除凭证，服务端仅保留凭证的哈希和对应缓存键。新报告删除时只发送凭证；旧报告保留旧删除入口。已删除、已过期和不存在的凭证返回幂等结果；进行中的同一分析取消后，写缓存前再检查取消状态。
- 评测输出默认仅保存用例编号、结构化统计和阶段耗时。仅对合成或获授权的脱敏材料临时保留回放输出，并单独设置过期时间。错误响应不返回模型正文。脱敏预览明确告知用户，删除本机记录无法撤回此前发给模型服务的文本。

## 4. 验证与发布门槛

| 验证项 | 做法 | 候选版通过条件 |
| --- | --- | --- |
| 程序可复现 | 用同一岗位评分表和证据快照回放 100 次；打乱模型返回顺序、增删无关字段。 | 总分、门槛和各维度贡献完全一致；无 `NaN`、越界分或分母漂移。 |
| 真模型稳定性 | T01–T07、N01–N03 分别运行 v1.3 和候选版。每例各做 5 次全链路冷启动、5 次固定评分表；T03 两种模式各扩到 10 次。 | 固定评分表下 T03 极差目标 ≤5 分，T01–T07 平均极差目标 ≤3 分。全链路单独报告极差、失败率和岗位条款变化，重点对照 v1.3。 |
| 语义与证据 | 两人独立标注至少 24 组样例及证据，按岗位隔离开发集和保留集，分歧复核后再对照。覆盖语义改写、无关经历、同词不同义、团队成果和虚构引用。 | 保留集上证据关联准确率目标 ≥90%，同时公开召回率、弃判率及分母；召回率不低于 v1.3，防止靠拒绝判断换高准确率。 |
| 硬性条件 | 设至少 40 条独立门槛用例，覆盖满足、明确冲突、未写、组合条件、单位及边界。 | 合成回归集里，未写或冲突事实造成的错误封顶为 0；明确满足和不满足的判断准确率目标 ≥95%，同时报告待确认比例。 |
| 异常与隐私 | 注入截断、缺失条目、限流、超时、并发取消、无效删除凭证和 OCR 脱敏样本。拦截真实出站请求并检查载荷、日志、缓存文件和报告。 | 样本中已覆盖的敏感字段外发及默认落盘均为 0；删除后无回写；模型失败有明确状态，不生成伪造的匹配分。 |
| 运行成本 | 同机器、同模型记录阶段耗时、成功率和 token。按无缓存、固定评分表、缓存命中分开统计。 | 无缓存成功率不得低于 v1.3；P95 耗时、平均 token 各不高于 v1.3 的 120%。达不到则压缩证据候选或缩小首发范围。 |

上述数字是验收目标。报告须同时给出样本量、失败数、待确认数和空分数。无分与失败不参与分数均值，但必须进入全样本成功率统计。条款一致性按规范化 JD 原文锚点对齐，跨版本对齐不到的条款单独列出，不能当成一致。

两版本的计划评测量约 **220 次分析**，模型调用数另计，按岗位评分表缓存策略和重试情况核算。固定模型别名、用例版本和模型参数，分别记录两个版本的提示词指纹，并交错运行，减少时段变化对比较的影响。先跑少量样例确认预算和脚本，再执行全量评测。真实模型复测只使用合成或获授权且脱敏的材料。

## 6. 实施与验收记录

- v1.4 候选实现在当前工作区启用，服务器支持用 `SCORING_STRATEGY=v1.3` 启动旧口径。新版缓存按策略和模型端点分开。
- 本地回归覆盖固定输入 100 次回放、43 个门槛样例、模型漏答和限流、脱敏、凭证删除与并发取消。Edge 模拟联调核对了确认前不提交、离线无分析请求、在线删除只发凭证。
- 双版本评测命令已通过模拟对照，支持冷启动和固定评分表、空分和失败分开计数、按原文锚点对齐，以及接入人工证据标注。命令和参数见 [评测说明](../tools/eval-cases/README.md)。
- [证据质量材料](../tools/quality-cases/README.md)已准备 24 组合成案例和标注草稿。开发集、保留集各 12 组，仍待独立复核。
- 2026-11-09 使用临时密钥完成 220 次真实模型对照。v1.4 出分 70/110，v1.3 出分 110/110。T03、T05 和 N02 在 v1.4 下均未出分，稳定性和出分率未达到本轮验收条件。详见[真实对照验收](./算法实测验收.md)。证据准确率和召回率仍待人工标签复核。
